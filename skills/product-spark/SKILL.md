# Spark Converger · 灵感收敛器

> 这是产品流程的 A 段。它不做判断（Audit 干那个），它只做收敛。
> 输入：散点想法。输出：1-3 个能脱口而出 target/场景/对手 的方向候选。

## 触发与定位

| 用户的状态 | 触发本 skill | 不触发本 skill |
|-----------|------------|--------------|
| "脑子里有几个想法都模糊" | ✓ | |
| "想从 obsidian 里挑一个方向" | ✓ | |
| "听了一圈朋友抱怨" | ✓ | |
| 已经知道要做什么、要审一下值不值得 | | → 直接走 `product-audit` |
| 完全没想法、要从头脑暴 | | → 先用 `brainstorming` 或 `obsidian` 做 fleeting/capture |

**和 brainstorming 的区别**：brainstorming 是把"一个明确想法"完善成可实施的设计；本 skill 是把"一堆散点"收敛成"几个能进 Audit 的候选"。前者从 1 到 1，后者从 N 到 1-3。

---

## 总流程（5 段）

```
触发 → 检查输入源
   ↓
Step 1 · Source       选输入源（obsidian / 口头 / 混合）
   ↓
Step 2 · Capture      取出原始想法 · 不评判
   ↓
Step 3 · Cluster      连点成线 · 找模式
   ↓
Step 4 · Converge     一次一问的 3-5 个多选 · 收敛到 1-3 个
   ↓
Step 5 · Candidate    输出候选（带 3 项最小输入预填）
   ↓
HARD GATE → 进入 product-audit
```

---

## Step 1 · Source（选输入源）

**风格**：教学态、不评判。一句话开场，问选哪个源。

```
开场："来收敛想法。先告诉我，要从哪里取出原料？

  1. 我口述/打字给你（你脑子里现成的想法）
  2. 从 obsidian 里拉（最近的 fleeting / topic / literature）
  3. 两者都有（先口述再补 obsidian）

选 1 / 2 / 3，或直接开始说。"
```

**遵循 superpowers/brainstorming 的"一次一问"原则**：这一步只问源，不问内容。

---

## Step 2 · Capture（取出原始想法）

### 如果选 1（口头）

让用户**一次性**把所有想法说完——不要打断、不要评判、不要追问。每个想法记下来即可。最少 3 条、最多 10 条。

```
"把脑子里所有想法都倒出来，一行一个。模糊的、半成形的、说不清的都行。
不评判，只是先列出来。说完打个'完'。"
```

### 如果选 2（obsidian）

调用 obsidian skill 的 query 模式，按以下顺序拉笔记：

1. 最近 30 天的 `fleeting/` 目录（闪念）
2. 最近 90 天有变动的 `Topic - *` 笔记
3. 用户给关键词时再追加 query

```bash
python ~/.claude/skills/obsidian/memory_manager.py \
  --vault "${OBSIDIAN_VAULT_PATH:-~/obsidian}" \
  --mode query \
  --keywords "<用户给的关键词，或留空抓最近 fleeting>"
```

把拉到的笔记**列表展示**（标题 + 1 行摘要），让用户勾选哪些算"想法源"——并不是所有笔记都要进 cluster。

### 如果选 3（混合）

先按"口头"流程跑，再跑 obsidian。把两边合并成一个**想法清单**。

### Capture 阶段的硬规则

- **不评判**：用户说"我想做一个 AI 给猫看的电视"——不能笑、不能说"这个不靠谱"，只记录
- **不追问**：模糊就模糊，Cluster 和 Converge 阶段会逼具体
- **数量下限**：少于 3 条，告诉用户"再想 5 分钟、回来加几条"或者"先用 obsidian 模式补"——少于 3 条不能进 Cluster

**输出**：一个想法清单（编号 1-N），原文保留。

---

## Step 3 · Cluster（连点成线）

**风格切换**：进入 Steve Jobs 的"连点成线"心智，但**不进角色扮演**——只是借用模式识别的视角。

### 3.1 找模式

把想法清单展示出来后，agent 自己做模式识别（不问用户）。找 3 类信号：

| 信号 | 怎么识别 |
|------|---------|
| **反复出现的目标用户** | 多个想法都指向同一类人（"独立开发者"/"内向的人"/"小团队 PM"） |
| **反复出现的痛点** | 多个想法都在解决同类问题（"信息过载"/"协作摩擦"/"重复劳动"） |
| **反复出现的技术拐点** | 多个想法都依赖同一个新能力（"LLM 能力"/"Agent 编排"/"本地模型"） |

输出格式：

```
我从这 N 条想法里看到 3 条线：

线 1：[反复出现的 X] —— 想法 #1, #4, #7 都指向这个
线 2：[反复出现的 Y] —— 想法 #2, #5
线 3：[反复出现的 Z] —— 想法 #3, #6, #8

落单：想法 #9, #10（不属于任何线，可能是噪音也可能是新苗头）
```

### 3.2 让用户挑

```
"这 3 条线里，哪一条最让你心动 / 最像你下一步真的想做？

  1. 线 1
  2. 线 2  
  3. 线 3
  4. 落单的某一条（说编号）
  5. 都不是 —— 我看漏了什么？

选一个，然后告诉我为什么是它。"
```

**关键设计**：让用户选**1 条**，不是 2-3 条。多选会让 Step 4 收敛失败。

---

## Step 4 · Converge（一次一问 · 收敛）

**风格切换**：进入收敛模式。借 brainstorming 的"一次一问、多选优先"协议。**最多 5 个问题**，少了就停。

### Q1：目标用户聚焦

```
"这条线的目标用户，最具体的是谁？

  1. [agent 基于线索给的候选 1，例：独立开发者中做 AI 工具的那批]
  2. [候选 2，例：刚从大厂出来的独立创业者]
  3. [候选 3，例：副业做产品的程序员]
  4. 都不对 —— 是 ___（用户填）"
```

### Q2：核心场景聚焦

```
"他们什么瞬间最痛、最会想到用你？

  1. [候选场景 1]
  2. [候选场景 2]
  3. [候选场景 3]
  4. 都不对 —— 是 ___"
```

### Q3：现状对手聚焦

```
"现在他们怎么解决这个问题？

  1. [真实竞品 A]
  2. [真实竞品 B]
  3. 用 Excel / 手工 / 找朋友帮忙
  4. 不解决，忍着
  5. 其他 —— 说"
```

### Q4（可选）：最锋利的差异化

```
"如果只能强调一个差异化点，是什么？

  1. 比对手快/便宜 X 倍
  2. 解决了对手解决不好的具体细节 [例]
  3. 服务对手忽略的小众用户 [例]
  4. 利用了对手没用到的新技术 [例]
  5. 其他 —— 说"
```

### Q5（可选）：要不要做候选 2/3

```
"我们现在有了一个具体方向。要不要也把另外 2 条线收敛一下，做成候选 2 和候选 3？
这样 Audit 时可以横向比较。

  1. 要 —— 都做
  2. 只做最有感觉的那 1 条候选 2
  3. 不要 —— 一个候选就够，直接进 Audit"
```

### 收敛规则

- 每个问题都给 **3-5 个候选 + "都不对，我说"** 的兜底
- agent 给的候选必须**基于 Cluster 阶段拿到的信息**（不能凭空编）
- 用户答 "都不对" → 接受用户填空，不强推 agent 候选
- 5 题问完即停。如果 5 题还不够清楚，**说明这条线还不够成熟**，建议回 Capture 补料

---

## Step 5 · Candidate（输出候选）

按 `template.md` 的格式输出 1-3 个候选，每个带 3 项最小输入**预填**：

```markdown
### 候选 1：[一句话方向]

- **target**：[Q1 答案]
- **核心场景**：[Q2 答案]
- **最强对手**：[Q3 答案]
- **差异化苗头**（可选）：[Q4 答案]
- **来源**：想法 #X, #Y, #Z（来自 Cluster 阶段的线 N）
```

### 候选数量硬规则

- **下限 1 个**：少于 1 个就是 Step 4 失败 → 回 Capture 重来
- **上限 3 个**：超过 3 个 = 没收敛 → 强制让用户砍到 3 个以内
- **建议 1-2 个**：3 个候选会让 Audit 阶段切来切去注意力涣散

---

## HARD GATE · 进 Audit 的入门检查

<HARD-GATE>
在把候选交给用户前，agent 必须自检以下 4 项。**任何一项不通过，禁止输出候选**——必须退回相应 Q 重问。

| 检查项 | 不通过怎么办 |
|--------|-----------|
| target 是不是具体角色？（不是"中小企业"/"年轻人"） | 退回 Q1 重问 |
| 核心场景是不是一个具体瞬间？（不是"日常使用"） | 退回 Q2 重问 |
| 最强对手是不是真名 + URL？（不是"某竞品"） | 让用户搜一下补上 |
| 候选数量在 1-3？ | 砍多 / 加少 |

**全部通过才输出**。不通过就**显式告诉用户**：「这个候选还差 X 项最小输入，咱们再问一轮。」

**不允许的事**：
- 不允许说"基本通过，先放过吧" —— 二元门，没有"基本"
- 不允许跳过检查直接生成候选 markdown
- 不允许把"用户/大家/年轻人"等放之四海皆准的 target 当成具体角色
</HARD-GATE>

### 输出收尾

```
"OK，候选准备好了：

[展示 1-3 个候选 markdown]

要不要现在直接进 Audit 把候选 1 审一遍？
（直接说 '审候选 1' / '审候选 2' / '都不审，先放着')"
```

## 落盘

候选默认保存到：

```
docs/sparks/YYYY-MM-DD-<主题>.md
```

方便 Audit 阶段引用，也方便 3 个月后回看"那时我考虑过这些方向"。

## Anti-Patterns

| 反模式 | 现场特征 | 纠正 |
|--------|---------|------|
| **跳过 Cluster** | 用户给了 5 个想法直接进 Q1 | 必须先做模式识别，否则就是流水账 |
| **Q1-Q5 全开放** | 不给候选只问"你觉得呢" | 必须给 3-5 个候选，多选优先 |
| **候选超过 3 个** | "我们做了 5 个候选" | 强制砍。Jobs：聚焦 = 说 No |
| **target 仍然是"用户"/"大家"** | HARD GATE 没拦住 | 退回 Q1，举例逼具体 |
| **进了角色扮演** | Cluster 阶段开始模仿 Jobs 语气 | Cluster 只借心智不演角色，演角色是 Audit Pass 2 的事 |
| **直接接到 PRD** | 候选出来后跳过 Audit 直接写 PRD | HARD GATE 之后只能进 Audit，不能跳段 |

## 诚实边界

1. **Cluster 模式识别可能漏**：agent 看到的"线"是基于词频和语义聚类，可能漏掉真正的洞察。落单的想法不一定是噪音，用户最好亲自扫一眼
2. **不替代 brainstorming**：如果用户连"想做点什么"都没有，本 skill 帮不上忙——先去 brainstorming 或 obsidian fleeting
3. **候选不等于答案**：本 skill 只输出"够格审计的候选"，不保证候选本身是好方向——这是 Audit 的事
4. **obsidian 笔记可能过时**：Step 2 拉的笔记如果是 6 个月前的，要提醒用户"这个想法当时的市场状态可能已经变了"
